# Обновления модов

Один публичный репозиторий `ontrey228/mod-updates`, ветка `main`.
Загрузите **содержимое** этой папки в корень репозитория, включая `.github`.
Сборки можно продолжать публиковать только в Telegram: здесь хранится один файл правил `updates.json`.
Исходный файл выключен: сначала замените ссылку на конкретный пост с доступной сборкой, затем включайте правило.

## Что менять для выпуска

В GitHub откройте `updates.json` → Edit. У нужного мода:

- `enabled: true` — проверять обновления; `false` — отменить и рекомендацию, и обязательное обновление.
- `latest.build` — **номер сборки**, например 60. Всегда увеличивайте его, даже если версия приложения осталась 13.1.
- `latest.version` — подпись версии, например `13.1`. На сравнение не влияет.
- `latest.url` — HTTPS-ссылка на сообщение Telegram со сборкой.
- `latest.notes` — краткое описание, можно оставить пустым.
- `minimumSupportedBuild: 0` — только рекомендация всем предыдущим сборкам.
- `minimumSupportedBuild: 60` — у сборок ниже 60 отключены функции мода до обновления.

Можно разделить границы: последняя сборка 65, минимальная 60 → у 59 и ниже отключены функции мода, 60–64 получают совет.
Не удаляйте продукт для отмены требования: поставьте `enabled: false` или `minimumSupportedBuild: 0`.
После сохранения подождите обновления GitHub CDN (обычно несколько минут). Для новой проверки полностью перезапустите мод.
Проверка GitHub Actions проверяет формат, но публикация через прямой коммит уже меняет файл;
для предварительной проверки используйте pull request или `python3 manage.py validate` до загрузки.

## Другие моды

Добавьте соседний объект в `products`, например `otherapp-ios`, с таким же блоком `channels.stable`.
Используйте отдельный ID для каждого приложения/платформы; Bundle ID и название приложения на него не влияют.
Для бета-сборок можно добавить `channels.beta` со своими номерами и правилами.
IPA и TIPA одного выпуска NeroGram имеют один номер и одно правило, ссылка ведёт на пост с обоими файлами.
Если разные варианты нужно обновлять независимо, используйте отдельные каналы и вшивайте нужный канал в вариант.
На iOS перенесите модуль `submodules/ModUpdates` целиком и подключите `ModUpdateCoordinator` в жизненном цикле приложения.
На Android можно использовать тот же JSON, реализовав клиент этого протокола.

## Необязательный помощник

Все команды выполняются в этой папке и меняют только локальный JSON. Затем загрузите его в GitHub.

```sh
python3 manage.py release --product nerogram-ios --version 13.1 --build 60 --url https://t.me/CHANNEL/123 --mode recommended
python3 manage.py release --product nerogram-ios --version 13.1 --build 60 --url https://t.me/CHANNEL/123 --mode required
python3 manage.py disable --product nerogram-ios
```

## Поведение клиента

Рекомендация: верхний баннер «Версия NeroGram устарела», «Обновить» и «Позже». Свайп вверх скрывает, вниз сразу открывает ссылку на обновление. Баннер не прерывает работу чата и клавиатуры. Рекомендация появляется один раз за полный запуск процесса. Обычное сворачивание её не повторяет; после удаления приложения из недавних и нового запуска она появляется снова. Пункта ручной проверки в настройках NeroGram нет.
Обязательное обновление: компактное предупреждение с кнопками «Обновить» и «Продолжить в Telegram». Отключаются только функции мода, Telegram и канал обновления остаются доступны. Ссылка на пост открывается внутри Telegram.

Правила проверяются при входе и каждые 15 минут работы; после ошибки повторная попытка возможна через минуту.
Ручная проверка обходит этот интервал, с защитой от повторных нажатий в течение 3 секунд.
Последнее корректное правило сохраняется между запусками. Сбой сети, 404 и испорченный JSON не создают блокировку.
Уже полученное обязательное правило действует и без сети; для его отмены клиент должен скачать исправленное правило.
Новый установленный билд сразу сравнивается с сохранённым минимумом, ожидать сети для разблокировки не нужно.
Отключаются функции мода через временную проекцию настроек. Сохранённые значения не сбрасываются и восстанавливаются после обновления или отмены требования. Основной Telegram, фоновые службы и расширения не отключаются.
Это механизм обновления, а не защита от модификации бинарника или удаления его данных.

Функция появится только у сборок, в которые включён клиент обновлений. Уже выпущенная сборка 58 проверку не содержит.
При проверке не передаются аккаунты, контакты, токены, номер телефона или сообщения.
GitHub видит обычный HTTPS-запрос; он должен отдавать JSON без авторизации. В репозитории не нужны токены или IPA.

Для другого приложения iOS нужно передать в `ModUpdateCoordinator.requiredUpdateChanged` обработчик, который временно отключает его функции мода. Сам координатор не знает устройства настроек чужого приложения.

Уведомления NeroGram следуют текущей теме Telegram, даже если она отличается от темы iOS. Цвета обновляются при смене темы без повторного показа уведомления.

Без интернета NeroGram использует последнее корректное правило. Без сохранённого правила ошибка сети не создаёт ограничений; сохранённое обязательное требование действует на функции мода до установки подходящей сборки или получения отмены. Для скачивания обновления требуется сеть.
